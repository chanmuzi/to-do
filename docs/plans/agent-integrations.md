# 에이전트 연동 기획 (보류 중인 초안)

상태: 기획만 해 둔 문서다. 구현을 시작하지 않았고, 어느 범위까지 갈지는 정하지 않았다(2026-11-24).
계정이나 조직에 따라 달라지는 사실은 일반적인 조건으로만 적었다.

## 목표

| 번호 | 목표 |
| --- | --- |
| G1 | 노트와 작업 현황을 오래 남는 곳(Apple 메모, Notion)에 보관하는 선택지 |
| G2 | iOS 앱 없이, 에이전트가 먼저 보내는 알림과 답을 메신저로 휴대폰에 전달. 대화 원본은 Float에 남김 |
| G3 | 캘린더, 메일, 문서 알림, 노트를 엮어 할 일의 완료 여부를 추적하고, 끝난 것으로 보이면 그만 묻기 |
| G4 | 조직 정책으로 앱 설치나 계정 연결이 막힌 곳은 우회로(알림 메일 등)로 |
| G5 | 이미 구독 중인 AI 서비스와 그 CLI, 공식 커넥터를 활용해 추가 비용 없이 |

## 원칙

- 계정에 닿는 일(로그인, 커넥터 연결, 인증)은 사용자가 직접 한다. 에이전트와 앱이 대신 시도하지 않는다.
- 계정이 걸린 연동은 시작 전에 사용자가 미리 할 일, 2단계 인증과 관리자 승인 여부, 보안 알림 가능성을 먼저 알린다.
- 에이전트의 읽기 범위는 좁게, 바꾸는 일은 제안과 승인으로(지금의 원칙 그대로). 메일 보내기와 지우기 같은 도구는 붙이지 않는다.
- 조직의 메일 내용이 AI 제공자나 개인 메신저로 나가도 되는지는 사용자가 조직 정책에 따라 판단한다.

## 먼저 확인할 세 가지(사용자가 직접)

1. Float의 격리된 CLI 실행에 구독 계정의 커넥터가 붙는가.
2. 클라우드 예약 실행이 Mac을 끈 상태에서 메일과 캘린더를 읽고 메신저 웹훅으로 보낼 수 있는가.
3. 문서 도구의 알림 메일 본문에 누가, 어느 페이지에, 무슨 말을 했는지가 들어 있는가.

## 추적 장부(설계 초안)

에이전트가 챙길 일을 한 줄씩 적어 두는 Float 안의 목록이다. 둘러볼 때마다 장부를 먼저 읽고 근거가 생긴 것만 상태를 바꾼다.

- 항목의 칸: 무엇, 출처와 근거 링크, 상태, 다음에 물을 때, 유효 기간, 상태를 바꾼 근거의 기록.
- 상태: 열림, 끝난 것으로 보임, 끝남, 버림, 닫음(유효 기간이 지나 한 번 묻고 닫음).

| 끝났다고 보는 근거 | 믿는 정도 | 행동 |
| --- | --- | --- |
| 노트의 할 일이 체크됨, 연결된 리마인더가 완료됨 | 확실 | 바로 끝남으로 |
| 같은 대화에 답장을 보냄, PR이 머지되거나 닫힘 | 높음 | 끝난 것으로 보임, 한 번 알림 |
| 일정이 지남, 질문에 답이 달렸다는 알림 | 보통 | 끝난 것으로 보임, 요약에 묶어 알림 |
| 유효 기간이 지남 | 근거 없음 | 한 번 묻고 닫음 |

- 장부의 상태는 승인 없이 적고 알림에 보기와 되돌리기를 둔다(기억과 같은 규칙). 노트, 일정, 보관소를 바꾸는 일은 지금의 제안과 승인을 그대로 쓴다.
- 라이브러리의 에이전트 구획에 추적 페이지를 둔다(새 화면, 시안 필요).

## 정할 것

1. 휴대폰으로 보내는 길: Discord 웹훅, Telegram 봇, 미리 알림만.
2. 메신저로 나가는 내용의 깊이: 제목만, 요약과 링크, 전문.
3. 격리를 어디까지: 앱이 만든 도구만, 구독 커넥터의 읽기 도구까지, 전부.
4. 메일을 읽는 길: 구독 커넥터, Mail 앱, 메일 API 직접.
5. Mac이 꺼졌을 때: 기다림, 클라우드 예약 실행 병행.
6. 보관소: Apple 메모, Notion.
7. 브라우저 결과를 받는 길: 받지 않음, 붙여 넣어 기록, CLI의 브라우저 도구.
8. 끝난 것으로 보일 때: 알리고 그만 묻기, 매번 확인, 조용히 닫기.

## 확인하지 못한 것

- 구독 커넥터가 엄격한 MCP 설정과 함께 붙는지, Codex의 화면 없는 실행에서 커넥터가 되는지.
- 웹훅으로 보낸 글의 휴대폰 푸시 조건, 클라우드 실행 환경에서 메신저로의 네트워크 허용.
- 문서 도구의 알림 메일 본문 형식, 조직 워크스페이스의 관리자 설정.
- Apple 메모로 보낼 때 서식이 얼마나 유지되는지.
