## 바로 다음에 할 일

1. **사용자 확인 결과 반영.** 사용자가 `docs/verification-checklist.md`를 실제로 해 보고 알려 준 것부터 고친다.
   특히 실제 마우스 클릭으로 노트가 앱을 활성화하는지, ⌘Tab과 Dock과 ⌘Z 경로, 실제 한글 입력기, 메뉴 막대 아이콘 폭.
2. **노트 제목 칸에 얇은 커서 연결.** 부품(`Theme`의 `ThinCaretFieldEditor`)은 있고 제목 칸만 시스템 커서를 쓴다.
   연결 순서는 `docs/architecture.md`의 Theme 절에 있다. `PlainTextBodyEditor`(편집기를 못 만들 때 쓰는 대체 편집기)도 같다.
3. **임시 결정 확인.** `docs/decisions.md`에서 상태가 `임시`인 줄을 사용자에게 한 번에 묻는다. 대표적인 것:
   - 오전/오후 없는 1~7시를 오후로 읽기(D-029), 본문 행간 22와 기호 간격 19(D-043), 커서 깜빡임 530ms(D-042)
   - 토스트 4초와 위치(D-039~D-041), 메인 메뉴 항목 배치, 아이콘 시각 보정값
   - 노트 최소 높이 4줄(D-031), 캡처 바 위치 화면 높이 20%(D-030), 메뉴 막대 아이콘 기본 표시(D-024)
   - 빈 노트를 "다른 노트가 대신할 때" 지우는 경우는 아직 흐름이 없음(D-040)

## 다음 단계

기획은 되었지만 아직 만들지 않은 단계다. 후속 세션에서 5단계부터 차례로 만든다(D-046).

| 단계 | 내용 | 먼저 읽을 것 |
| --- | --- | --- |
| 5 | 라이브러리(전체 노트 목록, 스페이스와 날짜 계층, 아카이브)와 스페이스 아이콘 고르기. 닫은 노트를 다시 여는 주된 길이 된다 | spec 09, 10, open questions 6~7 |
| 6 | 리마인더(설정, 표시, 알림)와 일정 | 이슈 #4, spec 20의 3, 8 |
| 7 | 테마 설정과 단축키 표 화면 | spec 12, 13 |
| 8 | AI 패널(Claude, Codex CLI 연결) | spec 11, D-004, D-005 |

- 지금 닫은 노트를 다시 여는 길: 메뉴 막대 아이콘이나 Dock 메뉴의 노트 찾기, 앱이 앞에 있을 때 ⌘P,
  떠 있는 노트가 없을 때 Dock 아이콘 누르기(최근 노트). 사용자가 찾기 어려워했다(2026-11-17).
- 5~8단계에 해당하는 메뉴 항목(라이브러리, AI 패널, 설정, 단축키, 리마인더 설정, 스페이스 옮기기)은 지금 흐리게 보이고 눌리지 않는다.
  `Route.isConnected`(App 타깃)가 그 단계의 화면이 생기면 켜는 한 곳이다.

### 6단계를 시작하기 전에 정할 것 (이슈 #4)

- 시간 범위가 있는 입력을 일정으로 등록할지, 어느 캘린더에 쓸지, 앱 리마인더를 Apple Reminders에도 쓸지.
- **사용자 결정(2026-11-17):** 빠른 캡처뿐 아니라 노트 본문과 제목에서도 날짜와 시간 표현을 인식해 제안한다.
  Tab 같은 키로 받아들이면 그 글자는 사라지고 리마인더나 일정으로 등록되거나 갱신된다. 이 기능은 6단계에 이어서 만든다.
- 날짜 읽기 규칙은 `docs/spec/07a-datetime.md`에 있고 시작과 종료 시각을 이미 돌려준다.

### 7단계에서 설정 화면에 꺼낼 값

- 인라인 코드 글자색(붉은 글자 기본, 흑백), 체크박스 모양: 이미 `app-settings.json`에 저장되고 열린 노트에 바로 반영된다(설정 화면만 없다).
- 메뉴 막대 아이콘 표시: 이미 저장된다.
- 본문 행간, 기호와 글자 사이 간격, 글꼴 크기: 토큰 덮어쓰기(`ThemeOverrides`)로 바꿀 수 있고 열린 편집기에 바로 반영된다.

## 알려진 한계 (고치지 않기로 했거나 미룬 것)

- 다크 모드에서 노트 테두리 바깥의 얇은 어두운 선은 시스템 창 그림자의 가장자리라 공개 API로 바꿀 수 없다.
  창 그림자와 배경 흐림은 시스템 기본값이다(`shadow-window`, `blur` 토큰 미적용, D-025).
- 영어 글자나 숫자 바로 뒤에서 시작하는 서식은 한 단어만 된다. 이를 깨는 편집은 경고음과 함께 거부한다(D-038).
- 줄 이동 명령은 부모 없는 자식 줄을 남길 수 있다. 줄 맨 앞의 `| `는 표가 아니라 인용이 된다.
  다른 앱이 쓴 `+ ` 목록은 토글로 읽힌다(D-043, D-044).
- 날짜 읽기에서 `금 3시`, `3월 3시`, `11-20 3시`는 `3시`만 읽는다. `주말`, `월말`, 날짜 없는 `다음 주`는 읽지 않는다(spec 07a).
- 서식 단축키는 한 줄 안의 선택에만 적용된다.
- 사용자가 한 번 본 "검은 잔상"은 재현하지 못했다. 다시 보이면 어떤 동작 직후였는지부터 묻는다.

## 작업 방식 메모

- 검증 중 사용자가 이 Mac을 쓰고 있다. 화면에 창을 띄우는 확인은 짧게, 보조 모니터 구석에서, 포커스를 가져가지 않게 한다.
  실행 옵션 `--notes-dir`, `--debug-passive`, `--debug-no-hotkeys`, `--menu-bar-icon off`와 `scripts/debug-send.sh`를 쓴다.
- 화면이 잠겨 있으면 창 단위 캡처가 실패한다. 앱 안의 스냅숏 명령으로 대신하고, 확인하지 못한 것을 그대로 적는다.
- 편집기는 원문이 보이지 않으므로 원문을 망가뜨리는 경로가 가장 위험하다. 편집기를 고치면 원문을 확인하는 테스트와 씨앗 고정
  퍼즈 테스트(`EditorFuzzTests`, `OutsideFuzzTests`, `UndoHistoryFuzzTests`)를 함께 돌린다.
