## 다음에 할 일

위에서부터 한다.

1. **8단계 에이전트 화면.** G0(실행기, 읽기 전용 MCP, 설정의 엔진 연결)까지 끝났다. 화면은 아직 없고 `Route.openAIPanel`만 `isConnected`가 거짓이다(App의 `AppRouter.swift`). 설계는 에이전트 시안 최종판(2026-11-23)으로 굳었다. 먼저 읽을 것: spec 11, 11a, 11b, 11c, D-190~D-202. 화면 값은 이미 확정됐으니 시안을 다시 만들지 않는다. 어두운 화면 값만 구현 뒤 캡처로 정한다(D-201).
   - 1단계: 막대의 두 모드, 에이전트 창(대화, 지난 대화, 진행 펼쳐 보기, 가장자리의 색), 얼굴 상태, 노트의 표시와 화면 구석 단추, 제안 카드와 미리보기, 사이드바의 제안과 대화 페이지, 볼 것 있음 점, 더하는 제안의 반영과 되돌리기, 메모리의 지침 문서, 막혔을 때의 안내. 제안 승인 쓰기 경로가 여기서 처음 생긴다. MCP는 계속 읽기만 한다(D-143).
   - 2단계: 루틴(목록, 만들기, 요약 확인, 테스트, 하나의 화면, 실행 대화, 되묻기와 알림), 지우기 확인 팝오버(루틴과 스페이스), 고치는 제안, 종류별 바로 반영.
   - 3단계: 메모리의 기억, 변경 기록과 되돌리기, 기억 정리, 일정에 맞춘 선제 알림.
   - 구현 전에 확인할 임시 값: spec 20의 14~17번.
   - 세 단계 뒤로 둔 것: API 키 경로(D-141), Google, Notion, 네이버 계정 연동(D-146).
2. **7단계 설정 후속.** spec 12 마지막 문단의 후속 항목이 아직 없다.
   - 테마 프리셋, 강조색과 기본 형광펜, 노트 색 팔레트 편집, 본문 글꼴 가족.
   - 창 투명도와 배경 흐림, 테마 JSON 가져오기와 내보내기.
   - 본문 기호와 글자 사이 간격 선택, 전역 단축키 변경과 등록 충돌 해결(단축키 화면은 지금 읽기 전용 표).
3. **본문 대체 편집기에 얇은 커서 연결.** 노트 제목 칸은 #34에서 `CommandInputField`를 거쳐 `ThinCaretFieldEditor`를 쓴다(D-132). 남은 것은 `PlainTextBodyEditor`(편집기를 못 만들 때 쓰는 대체 편집기)로, 아직 시스템 커서에 색만 바꾼다. `docs/architecture.md` Theme 절과 checklist의 "제목 칸 커서" 줄은 연결 전 내용이라 함께 고친다.
4. **사용자 확인.** 사용자가 `docs/verification-checklist.md`를 실제로 해 보고 알려 준 것부터 고친다. 특히 실제 마우스 클릭의 앱 활성화, ⌘Tab과 Dock과 ⌘Z 경로, 실제 한글 입력기, 메뉴 막대 아이콘 폭, EventKit 실제 권한과 업데이트 뒤 권한 유지, iPhone 반영.
5. **남은 임시 결정.** D-014~D-095의 임시 28건은 정리했다(2026-11-20, D-157~D-161): 사용자가 정한 7건은 새 결정으로, 뒤 결정이 바꾼 10건은 `대체됨`, 내부 판단 11건은 `현행`.
   남은 `임시`는 D-160(직접 정한 노트 높이를 저장하지 않음)이다. 휴지통은 자동으로 비우지 않기로 했다(D-161).

- 닫은 노트를 다시 여는 주된 길은 라이브러리다. 메뉴 막대, Dock, 앱 메뉴, 노트 찾기에서 열고, ⌃⌥L을 쓴다.
  떠 있는 노트가 없는 앱 시작과 Dock 재열기도 라이브러리로 간다. 메뉴 막대 아이콘을 꺼도 이 경로들이 남는다.
- 날짜 읽기 규칙은 `docs/spec/07a-datetime.md`에 있고 시작과 종료 시각을 이미 돌려준다.

## 알려진 한계 (고치지 않기로 했거나 미룬 것)

- 다크 모드에서 노트 테두리 바깥의 얇은 어두운 선은 시스템 창 그림자의 가장자리라 공개 API로 바꿀 수 없다.
  창 그림자와 배경 흐림은 시스템 기본값이다(`shadow-window`, `blur` 토큰 미적용, D-025).
- 영어 글자나 숫자 바로 뒤에서 시작하는 서식은 한 단어만 된다. 이를 깨는 편집은 경고음과 함께 거부한다(D-038).
- 줄 이동 명령은 부모 없는 자식 줄을 남길 수 있다. 줄 맨 앞의 `| `는 표가 아니라 인용이 된다.
  다른 앱이 쓴 `+ ` 목록은 토글로 읽힌다(D-043, D-044).
- 날짜 읽기에서 `금 3시`, `3월 3시`, `11-20 3시`는 `3시`만 읽는다. `주말`, `월말`, 날짜 없는 `다음 주`는 읽지 않는다(spec 07a).
- 서식 단축키는 한 줄 안의 선택에만 적용된다.
- 사용자가 한 번 본 "검은 잔상"은 재현하지 못했다. 다시 보이면 어떤 동작 직후였는지부터 묻는다.

## 작업 방식 메모

- 구현과 실행 확인은 Codex가, 범위, 리뷰, 커밋과 PR은 Claude가 맡는다(2026-11-17 사용자 결정). Codex는 사용자가 볼 수 있는 Orca 탭에서 돌린다.
- 기본 빌드 경로는 `build/Float.app`이다. 사용 중인 묶음을 보호하도록 확인용 빌드는 `FLOATING_NOTES_APP_DIR`로 다른 곳에 만들고, 프로세스는 이름이 아니라 띄운 PID로만 끝낸다.
- 검증 중 사용자가 이 Mac을 쓰고 있다. 화면에 창을 띄우는 확인은 짧게, 보조 모니터 구석에서, 포커스를 가져가지 않게 한다.
  확인용 묶음은 `FLOATING_NOTES_APP_DIR=<작업 폴더>/app`으로 분리한다. 실행 옵션 `--notes-dir`, `--debug-passive`, `--debug-no-hotkeys`, `--menu-bar-icon off`와 `scripts/debug-send.sh`를 쓴다.
- 화면이 잠겨 있으면 창 단위 캡처가 실패한다. 앱 안의 스냅숏 명령으로 대신하고, 확인하지 못한 것을 그대로 적는다.
- 편집기는 원문이 보이지 않으므로 원문을 망가뜨리는 경로가 가장 위험하다. 편집기를 고치면 원문을 확인하는 테스트와 씨앗 고정
  퍼즈 테스트(`EditorFuzzTests`, `OutsideFuzzTests`, `UndoHistoryFuzzTests`)를 함께 돌린다.
