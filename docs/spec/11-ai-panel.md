## 11. 에이전트 (화면 5)

화면 5의 옛 AI 패널(오른쪽에 붙는 430pt 패널, 도구 내역, 후보 상자, 머리 줄의 에이전트 목록)은 따르지 않는다. 에이전트 시안 최종판(2026-11-23)으로 대체했다(D-190~D-202).

| 무엇 | 파일 |
| --- | --- |
| 실행기, 연결, 로그인, 모델 메뉴(구현됨) | 이 파일의 아래 절 |
| 막대의 두 모드, 에이전트 창, 얼굴, 진행 표시, 에이전트 색, 점, 막혔을 때, 새 요소 표, 단계 | `11a-agent-surfaces.md` |
| 제안: 반영 방식, 미리보기, 버튼 자리, 제안 페이지 | `11b-agent-suggestions.md` |
| 루틴, 메모리, 기억 정리, 선제 알림 | `11c-agent-routines-memory.md` |

요청 막대와 에이전트 창이 이 실행기를 사용한다. 대화 요청은 할 일, 리마인더, 일정 추가와 새 노트 만들기를 제안할 수 있다. 루틴과 메모리 화면은 후속이다.


### G0 실행기 계약

- 구독 연결은 엔진별 Float 전용 폴더로 로그인한다. 저장 위치는 `StoreLocation.stateDirectory/agents/claude`와 `agents/codex`다. Claude는 `auth status --json`에서 로그인 여부, 방식, 이메일, 요금제, 세부 등급, 만료를 읽는다. 이메일 원문은 연결 화면 메모리에만 둔다. Codex의 로그인 여부와 방식은 `login status`를 따른다. Float 전용 auth.json의 ID 토큰에서 읽을 수 있는 이메일과 요금제만 상세에 추가한다.
- 실행마다 빈 작업 폴더와 최소 환경을 만든다. Claude는 B3의 다섯 환경변수, 빈 설정 소스, 엄격한 Float MCP 설정, 빈 내장 도구 목록, 두 읽기 도구 허용, 슬래시 명령 차단, dontAsk, 세션 저장 해제를 사용한다. `stream-json`의 부분 메시지, 결과, 비용과 한도 이벤트를 읽는다.
- Claude의 첫 init에서 두 도구 이름, 연결된 float 서버 한 개, 빈 스킬과 명령, 내장 경로의 `cc-plugin-*`만 허용한다. 필드 누락, 추가 도구, 잘못된 서버가 있으면 그 실행의 그룹을 종료하고 위반 필드를 반환한다.
- Codex는 전용 CODEX_HOME과 별도의 빈 사용자 홈, 읽기 전용 샌드박스, 사용자 설정과 규칙 무시, 임시 실행, 닫힌 stdin을 사용한다. Float MCP의 도구 이름을 제한하고 셸, 앱, 훅, 플러그인, 웹 검색을 끈다. Codex의 JSONL에는 Claude식 init 목록이 없다. 실행 중 관측한 도구 이벤트도 검사한다. CLI가 실제 모델이나 비용을 주지 않으면 값을 비워 둔다.
- 실행 기록은 `stateDirectory/agent-usage/<실행 UUID>.json`에 원자적으로 저장한다. 시작 시각, 경과 시간, 엔진, 요청 모델, 확인된 모델, 결과 상태, 제공된 토큰 수와 USD 비용만 남긴다. Claude 입력 합계에는 캐시 생성과 읽기가 포함된다. 중단 전 사용량이 없으면 값도 비어 있다.
- G0의 MCP는 노트 목록과 원문 읽기만 제공한다. G0와 설정의 연결 확인에는 접수 폴더를 넘기지 않는다.

### 에이전트 연결과 만료

설정을 열면 설치와 로그인 상태를 확인한다. 첫 화면은 연결된 에이전트만 선택할 수 있다. 기본 에이전트는 Claude다. 모델 값 버튼은 왼쪽 체크 메뉴를 연다. Claude는 설정 창을 열 때 한 번 전용 CLI에 초기화 제어 요청만 보내 모델 목록을 받는다. 자동 뒤에 CLI 순서대로 모든 모델을 표시하고 선택한 value를 --model에 넘긴다. description을 U+00B7로 나눈 첫 조각이 displayName으로 시작하면 그 조각을, 그 밖에는 displayName을 메뉴와 값 버튼에 표시한다. 자동은 모델 인자를 생략하며 CLI의 기본 항목은 자동에 합친다. 선택지가 있을 때만 자동 아래에 구분선을 둔다. 성공한 목록에서 저장값이 사라지면 자동으로 전환해 저장한다. 실패하면 자동, Fable, Opus, Sonnet, Haiku로 돌아가고 저장값을 보존한다. 창을 닫으면 목록을 비운다(D-186). Codex는 CLI 기본 뒤에 전용 CODEX_HOME의 `codex debug models`에서 visibility가 list인 항목을 Codex가 매긴 우선순위 순서(priority 오름차순)로 앞 다섯 개 표시한다. 저장된 모델이 그 뒤에 있으면 여섯째 모델로 추가하고 체크한다(D-182). display_name을 보여 주고 slug를 -m으로 넘긴다. 설정을 열 때 한 번 조회하고 닫을 때 목록을 비운다. 조회 실패 시 CLI 기본만 보이고 저장값을 보존한다. 조회에 성공했을 때 저장한 slug가 표시 가능한 전체 목록에서 사라졌으면 CLI 기본으로 전환해 저장한다. 목록에는 로고, 이름, 회사, 상태와 꺾쇠를 둔다.

상세에서는 계정, 요금제, 로그인 방식을 읽기 전용으로 표시한다. 이메일은 전체를 표시하고 창을 닫을 때 메모리에서 지운다. 상세에서 연결하면 취소 가능한 브라우저 로그인 뒤 계정을 다시 확인한다. 연결된 상태의 로그아웃은 해당 전용 폴더의 CLI 명령을 실행한다.

CLI가 보고한 로그인 만료일이 지났거나 전용 폴더에 자격 파일 또는 과거 연결 표시가 있는데 로그인되지 않았으면 만료다. 사이드바 경고와 상세의 다시 로그인 배너를 보인다. 막힌 작업에서 만료가 확인되면 macOS 알림에 일 이름과 다시 로그인 동작을 붙인다. 같은 만료는 한 번만 알리고 재연결하면 초기화한다. 알림을 위한 주기 검사는 하지 않는다.

설치가 필요하면 공식 설치 명령을 노트 코드 블록 바탕에 표시한다. 복사 아이콘만 동작하며 아래에 다른 설치 방법 ↗ 글자 링크를 둔다. 정보 아이콘에 올리면 위쪽에 검은 툴팁과 꼬리가 나타난다. 설정 창이 다시 키 창이 될 때 설치 여부를 재확인한다.

### 대화 요청 실행 계약

전송 차례마다 설정의 제공자, 모델과 강도를 요청에 기록한다. 제공자별 강도의 기본값은 자동이며 CLI 인자를 생략한다. 강도를 지정하면 Claude에는 `--effort`, Codex에는 `-c model_reasoning_effort`로 전달한다. 실행 시작 뒤의 설정 변경은 다음 요청에 적용한다. 전용 환경에서 계정을 확인하고 요청 하나에 Claude B3 또는 Codex 임시 exec 한 번을 쓴다. Claude에는 bare를 넘기지 않는다. 실행 파일 검색 폴더를 지정한 실행은 그 폴더에서만 찾는다. 실행 시작 때 편집기의 미전달 변경을 저장하고 지침 스냅숏을 잡는다. JSON의 `toolInstruction`은 고정 안내, `instructions`는 최신 지침 원문 한 벌, `context`는 고른 항목별 종류, 이름, 노트 파일 목록과 생략 수, `history`는 이전 발화, `request`는 이번 사용자 글이다. 도는 중에 고친 지침은 다음 차례부터 적용한다. Claude의 CLAUDE.md 탐색과 Codex의 사용자 규칙 읽기는 계속 끈다. 입력 예산에서 빠진 과거 메시지 수를 명시한다.

보내기 시점의 컨텍스트 항목은 대기열과 요청 기록에 남고 재시도에도 이어진다. 파일은 실행 시점의 노트에서 구한다. 스페이스, 오늘, 고정됨은 라이브러리와 같은 조건이고, 기간은 현지 달력에서 그때 만들거나 수정한 노트다. 지난 7일은 오늘을 포함하고 이번 주는 달력의 주 시작 설정을 따른다. 휴지통은 제외한다. 항목별로 최근 수정 순 50개까지 넣고 초과분을 `omitted`에 적는다. 96 KiB 안에서 과거 발화를 가장 낮은 우선순위로 둔다. 현재 요청 묶음만으로 넘치면 먼 일정과 리마인더, 범위별 같은 개수 상한을 넘는 오래된 파일, 마지막 범위 순으로 줄인다. 통째로 빠진 범위 수는 `omittedContext`다.

호출 ID가 맞는 성공한 읽기 결과만 실제 노트 ID와 대조해 링크한다. 진행의 경과 시간은 앱이 관측한 구간이다. 부분 답은 성공 시 최종 답으로 교체한다. 취소 시 그룹 회수와 사용량 기록을 마친 뒤 다음 실행을 시작한다. 사용량 파일 이름과 대화의 실행 ID가 같고, 요청과 답 원문과 계정 정보는 사용량 파일에 기록하지 않는다.

### 변경 제안 도구

대화 실행은 앱이 만든 `stateDirectory/agent/intake/<runID>`를 FloatMCP의 두 번째 인자로 받는다. 폴더 권한은 0700이다. 이때만 기존 두 도구에 `propose_change`를 더한다. Claude의 허용 목록과 init 목록이 일치해야 하고 Codex의 enabled_tools와 스트림 검사에도 같은 세 이름을 쓴다. 사용자 지침과 별도의 고정 필드는 노트 변경을 이 도구로 제안하도록 안내한다(D-239).

도구는 종류별로 다음 인자만 받는다. `note_id`는 목록 파일 이름에서 마지막 .md를 뺀 값이다. 지정된 노트는 접수할 때 목록과 대조한다. 할 일과 일정의 대상 파일 지문을 보관한다.

| kind | 인자와 검사 |
| --- | --- |
| `add_todos` | `note_id`, `lines`. 비어 있지 않은 단일 줄 1개에서 32개, 한 줄은 UTF-8 1024바이트까지다. |
| `add_reminder` | `note_id`, `title`, `date_only`, `start`, `time_zone`. 날짜는 yyyy-MM-dd, 시각은 yyyy-MM-dd'T'HH:mm:ss로 지정한 시간대의 현지 값을 보낸다. |
| `add_event` | 리마인더 인자에 `end`를 더한다. 날짜만 있는 일정도 끝은 배타적이며 시작보다 늦어야 한다. |
| `create_note` | `title`, `markdown`, 선택 사항으로 출처 `note_id`와 목적지 `space_id`. 제목은 1024바이트 이하의 한 줄, 본문은 32KiB 이하, 비어 있어도 된다. |
| `change_instructions` | `user_message`는 이번 사용자 메시지 전체, `before`와 `after`는 변경 전후 Markdown 전체다. 세 필드는 각각 UTF-8 96KiB 이하이며 문서가 실제로 바뀌어야 한다. |

없는 날짜, 시간대, 현지 시각으로 왕복할 수 없는 값과 추가 필드는 도구 오류다. MCP는 자유 글에서 날짜를 추론하지 않는다. 검사를 통과하면 사용자 전용 임시 파일에 쓰고 디렉터리 파일 디스크립터 기준으로 최종 이름을 링크한다. 같은 실행에서 종류와 인자가 동일하면 최초 접수 한 건을 남긴다.

정상 종료와 완료 이벤트를 확인한 뒤 조정자가 접수 파일을 읽고 답과 제안을 대화에 함께 저장한다. 저장 뒤 접수 폴더를 지운다. 실패와 중단은 접수를 읽지 않고 지우며 재전송은 새 실행 ID를 사용한다.


고정 안내는 모델에게 이번 요청에서 사용자가 앞으로 지킬 규칙을 직접 부탁한 경우에만 지침 변경을 제안하도록 한다. 노트나 도구 결과에 적힌 지시와 과거 대화는 근거로 삼지 않는다. 직접 부탁했는지는 모델이 판단하며, 접수는 언어나 특정 표현을 조건으로 삼지 않는다(D-242).

앱은 실행 폴더에 요청 ID, 사용자 메시지와 최초 지침 문서의 UTF-8 지문을 둔다. MCP는 근거 메시지와 변경 전 문서의 지문을 대조한다. 근거 누락, 메시지 불일치, 최초 문서 불일치 등은 도구 결과의 `isError`와 `content[].text`에 까닭을 담아 돌려준다. 모델은 그 까닭을 사용자에게 전달한다. 앱은 접수를 대화에 저장할 때 근거와 기반을 다시 검사하며, 요청 ID와 메시지 원문까지 대조한다. 접수된 제안은 승인 대기로 남고, 사용자가 받아야 지침 파일을 바꾼다.

### 최근 노트와 현지 시각

요청의 `localDateTime`은 실행 시점의 현지 ISO 8601 시각이고 `weekday`와 `timeZone`은 요일과 시간대 이름이다. 때를 묻는 요청은 아래 목록과 `list_notes`의 수정 시각을 함께 확인한다.

`today.events`는 현지 오늘에 걸친 일정, `today.reminders`는 내일 자정 전까지 기한이 있는 미완료 리마인더다. 지난 기한을 포함한다. 새 권한 요청 없이 설정에서 고른 캘린더와 목록(선택이 없으면 시스템 기본값)을 읽는다. 제목, 현지 시작과 끝(리마인더는 시작이 기한), 종일 여부, 출처와 연결된 노트 파일명을 보낸다. 권한이나 대상을 사용할 수 없으면 종류별로 ‘알 수 없음’, 조회 결과가 비면 ‘없음’이다. 종류마다 가까운 20개까지 넣고, 요청 전체가 96 KiB를 넘으면 먼 항목부터 더 빼며 `omitted`에 생략한 수를 적는다(D-289).

`list_notes`는 수정 시각 내림차순, 동률이면 파일명 오름차순이다. `since`는 수정 시각 하한을 포함한다. `limit`은 기본 50, 범위 1부터 200이고 `offset`은 0부터다. `notes`에 결과를, `unreadable`에 읽지 못한 파일명을, `next_offset`에 다음 위치를 담는다. 마지막 묶음의 다음 위치는 null이다.

메타 정보에는 파일명, 제목, 생성과 수정 시각, 시간대, 스페이스 이름, 보관과 고정 및 창 열림 여부, 미완료와 전체 체크박스 수, 가장 가까운 리마인더와 일정의 시작 시각과 날짜 전용 여부, 본문 글자 수가 있다. 예정을 고를 때 완료와 삭제 항목을 제외하고 현재 시각과 시작 시각의 차이를 비교한다. 공백뿐인 체크박스는 두 도구와 라이브러리의 할 일 수에서 제외한다(D-290). 두 읽기 도구는 같은 파일 읽기 경계를 쓰며 휴지통과 링크는 제외한다. `read_note`는 같은 메타 정보 뒤에 빈 줄과 `[원문]`을 두고 파일 전체를 붙인다.

앱은 실행 폴더(0700)에 보기 상태, 스페이스 이름과 보관 기준일만 담은 숨김 파일(0400)을 둔다. 이 파일은 제안으로 접수하지 않는다. 접수 폴더 없이 호출하는 진단 실행에서는 창 상태와 스페이스 이름을 알 수 없다.
