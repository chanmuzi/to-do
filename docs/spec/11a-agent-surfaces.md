## 11a. 에이전트의 화면 요소

1단계 PR 2에서 전체 노트 요청 막대, 노트별 대화 창의 전송, 두 엔진의 읽기와 답변, 진행, 재시도와 줄 세우기를 연결했다. PR 3에서는 시계의 지난 대화, 새 대화, 라이브러리 진입, 노트와 화면 구석의 표시를 연결했다.

근거는 에이전트 시안 최종판(2026-11-23)이다. 치수와 색은 그 시안을 만든 생성 스크립트의 CSS 값이 정본이고, 아래 값은 거기서 옮긴 것이다. 어두운 화면 값은 구현 뒤 캡처로 정한다(사용자 결정, D-201).

원칙: 대화창 하나에서 모든 일을 처리하지 않는다. 노트 글에서 요청을 알아채지 않는다. 요청은 막대와 에이전트 창에서만 받는다(D-190).

### 막대의 두 모드

빠른 캡처 바(7장) 하나에 두 모드를 둔다. 크기와 자리는 7장 그대로다.

| 모드 | 여는 길 | 왼쪽 표시 | 하는 일 |
| --- | --- | --- | --- |
| 요청(기본) | ⌃⌥A, 메뉴 막대, 라이브러리 | 얼굴 | 에이전트에게 요청을 보낸다. 읽을 범위는 언제나 전체 노트다 |
| 메모 | ⌃⌥N | 기존 캡처 표시 | 지금의 빠른 캡처 그대로 |

- 각 모드의 초안은 전환할 때 복원한다. 요청은 날짜 해석과 오늘 노트 저장을 거치지 않는다.
- 왼쪽 표시를 누르거나 다른 쪽 단축키를 누르면 모드가 바뀐다.
- 요청 모드에서는 Return으로 보낸다. 막대가 닫히고 그 화면의 에이전트 창이 새 대화로 바뀐다. 입력 중이던 다른 대화의 초안과 이전 대화는 저장된다. 이어 묻기는 창의 입력 칸을 쓴다.
- 요청 막대를 다시 열면 입력 칸 아래에 직전 물음, 답의 첫 줄, 지난 시간이 보인다. 모두 막대 입력 칸과 같은 글꼴을 쓰며 물음과 답은 13pt, 지난 시간은 12pt다. 진행 중이면 얼굴과 진행 문구를 보이고 줄을 누르면 해당 대화를 연다. 삭제한 대화는 숨긴다.
- 막대 요청의 진행과 답은 창 안에서 이어진다. 같은 대화가 보이는 창이 없거나 최소화되거나 완전히 가려졌으면 macOS 알림을 보낸다. 제목은 물음, 본문은 서식을 벗긴 답의 첫 두 줄이다. 알림 본문이나 보기를 누르면 그 대화로 간다. 알림 권한이 없으면 로그만 남긴다.
- 창 입력에서 보낸 요청은 기존 완료 알림을 쓴다. 결과 줄은 제안 ID로 해당 카드를 연다.

### 에이전트 창

- 떠 있는 창 하나에 대화 하나다. 크기와 모서리, 머리 줄(높이 32pt)은 노트 창과 같다.
- 머리 줄: 얼굴과 대화 이름, 오른쪽에 지난 대화(시계), 새 대화(+), 더 보기, 구분선, 닫기.
- 창 머리의 더 보기에는 이름 바꾸기, 구분선, 지우기가 있다. 한 번도 보내지 않은 초안에서는 두 명령이 비활성이다. 이름은 머리에서 편집하고 삭제하면 창이 닫힌다.
- 노트와 구분하는 표시는 가장자리뿐이다. 평소에는 1pt의 에이전트 색 선, 일하는 동안에는 1.5pt로 흐르고 바깥으로 3pt 옅게 번진다.
- 여는 길: 노트 상단 조작 줄의 얼굴이나 ⌘J(그 노트가 대상), 요청 막대의 Return과 직전 답 줄, 라이브러리 대화 페이지의 줄을 두 번 누름, 화면 구석 단추.
- 내 말은 오른쪽 말풍선, 에이전트의 답은 왼쪽에 얼굴과 함께 말풍선 없이 둔다. 답은 창에, 제안 카드는 대상 노트 아래에 붙는다.
- 입력 칸의 자리 글자는 `에이전트에게 요청하기`, 오른쪽에 위쪽 화살표 아이콘 버튼.
- 라이브러리 사이드바의 에이전트 구획에는 현재 대화 한 줄을 둔다. 제안, 루틴, 메모리는 기능이 생길 때 추가한다. 대화 페이지는 날짜로 묶은 지난 대화 목록이고 `새 대화`는 페이지 머리 오른쪽 +다. 사이드바 구획 머리의 얼굴은 막대를 연다(D-210). 시계와 라이브러리는 첫 요청을 보낸 대화만 같은 날짜 구획으로 표시한다. 새 대화는 초안을 따로 연다.

첫 창은 같은 화면에서 노트 오른쪽, 왼쪽, 비스듬히 겹치는 순서다. 전역에서 열면 포인터 화면의 오른쪽 위에서 노트를 피한다. 폭은 340pt, 범위는 260~560pt다. 높이는 내용에 맞춰 420pt와 화면 표시 영역 70% 중 작은 높이까지 자란다. 손으로 더 크게 만든 창은 유지한다. 넘치는 답은 창 안에서 스크롤한다. 맨 아래에서 새 글을 따라가고, 위로 올리면 읽던 자리에 머문다. 다시 바닥에 닿거나 입력 칸 위의 맨 아래로 단추를 누르면 따라간다(D-271, D-274).

### 요청 줄과 멈춤

막대와 창은 앱 전체의 한 실행 차례를 공유한다. 실행 전에는 해당 대화 입력 칸 위에만 줄 선 글이 보인다. 성공을 저장한 뒤 차례대로 시작하고 실패하면 대기한다. 다시 시도는 같은 사용자 요청에 새 실행 ID를 쓴다. 창을 닫아도 실행한다. 종료 중이거나 다음 실행에 실행 중으로 남아 있는 요청은 ‘앱을 끄면서 멈췄어요’와 진행을 남긴다. 다음 시작에 처음부터 다시 보내고 앱 전체의 대기열을 이어 보낸다. 매 시도에는 새 실행 ID를 주며 말풍선은 한 번만 표시한다. 창을 열거나 앱을 활성화하지 않고 완료 알림을 낸다. 사용자가 멈춘 요청과 실패한 답은 자동 재시도 대상에서 제외한다. 옛 파일에서 종료 사유가 없는 중단은 재전송하지 않는다. 전송 순번이 없는 옛 줄은 같은 파일 안의 순서를 보존하고 대화 사이에서는 활동 시각과 ID 순을 쓴다.

앞 요청의 실패로 멈춘 줄은 재시작 후에도 대기한다. 시작할 때 연결이나 설치를 확인할 수 없으면 중단 요청을 맨 위에 두고 대기한다. 두 경우 모두 해당 대화의 줄 위에 ‘보내지 않은 요청 N개’, ‘모두 빼기’, ‘모두 보내기’를 표시한다. 모두 빼기는 확인 없이 그 대화의 줄을 비우고, 모두 보내기는 맨 위부터 실행한다. 버튼 간격은 6pt, 좌우 안쪽은 8pt, 높이는 22pt다. 좁으면 버튼 묶음이 4pt 아래 오른쪽으로 내려간다.

줄의 고치기는 빈 입력 칸으로 글을 옮긴다. 쓰던 초안이 있으면 고치기를 비활성화한다(D-219, 임시). 빼기는 해당 줄 하나를 지운다. 지금 보내기는 실행 중인 그룹을 회수한 뒤 선택한 요청을 시작한다. 기존 부분 답과 단계 아래에 ‘여기서 멈췄어요’를 표시하고 나머지는 차례를 유지한다. 줄의 칸 크기와 간격을 별도 토큰으로 둔다. Q2 (나)로 20pt 칸 사이 2pt, 글과 아이콘 묶음 사이 8pt를 확정했다. 다른 줄은 24pt 칸 사이 2pt다(D-221).

### 얼굴

에이전트의 표시는 얼굴 하나다. 제공자 로고는 설정에만 쓴다.

| 상태 | 옆의 글 | 모습 |
| --- | --- | --- |
| 쉬는 중 | 없음 | 가끔 눈을 깜박인다 |
| 듣는 중 | 듣는 중 | 고개를 기울인다. 16pt부터 옆에 소리 물결이 차례로 켜진다 |
| 생각하는 중 | 생각하는 중 | 눈이 위를 보고 점 셋이 차례로 켜진다 |
| 노트를 읽는 중 | 읽는 중 | 눈이 글줄을 따라 왼쪽에서 오른쪽으로 간다 |
| 적는 중 | 적는 중 | 눈이 아래를 보고 연필이 움직인다 |
| 찾는 중 | 찾는 중 | 눈이 좌우를 살피고 돋보기가 돈다 |
| 기다리는 중 | 답이 필요해요 | 빨간 물음표(`warn`)가 살짝 떠오른다 |
| 끝남 | 결과 한 줄(예: 제안 2개) | 웃는 눈과 체크. 움직이지 않는다 |
| 막힘 | 막혔어요 | 눈이 일자가 되고 빨간 느낌표. 움직이지 않는다 |
| 기억 정리 중 | 기억 정리 중 | 눈을 감고 z가 떠오른다 |

- 크기 규칙: 13, 14pt는 눈 모양과 움직임, 볼 것이 있으면 점만. 16pt는 구석 기호까지. 20pt 이상은 소품까지. 글은 언제나 옆에 함께 둔다.
- 자리: 노트 상단 조작 줄(평소에는 숨고, 일하는 중이거나 볼 것이 있으면 남는다), 사이드바의 제안 줄, 에이전트 창의 머리 줄과 답, 알림, 화면 구석 단추.
- 화면 구석 단추는 화면 오른쪽 아래의 지름 40pt 원이다. 쉬는 중, 일하는 중, 볼 것 있음을 보이고 누르면 에이전트 창이 열린다.
- 설정의 에이전트 표시 카드에서 `노트에 표시`와 `화면 구석 단추`를 따로 켜고 끈다.
- 움직임 줄이기가 켜져 있으면 움직이지 않는 모습만 쓴다(15장의 규칙).

### 진행 표시

- 돌아가는 표시를 쓰지 않는다. 일하는 중은 글자 위로 밝은 띠가 흐르는 것으로 알린다.
- 접힘: 한 줄(지금 하는 일의 글자 흐름과 오른쪽 꺾쇠).
- 펼침: 단계 목록. 끝난 단계는 체크와 걸린 시간, 글자는 12pt `text-2`. 진한 글자는 노트 이름이고 누르면 그 노트가 뜬다.
- 끝난 뒤에는 한 줄로 접히고 다시 펼 수 있다.

### 에이전트 색

낮은 채도의 두 색(옅은 라벤더에서 모래빛)이다. 쓰는 곳은 셋뿐이다.

1. 일하는 중: 글자 흐름, 일하는 중 알림과 줄의 테두리.
2. 아직 받지 않은 제안: 카드, 연결 줄, 미리보기의 점선.
3. 에이전트 창의 가장자리.

받거나 버리면 색이 사라진다. 버튼, 목록 줄, 사이드바, 글자와 아이콘에는 쓰지 않는다.

### 볼 것 있음 점

- 점은 지름 6pt로 줄 끝에서 4pt 안쪽에 둔다. 날짜가 있으면 날짜에서 8pt 뒤다. 올리면 날짜와 점 자리에 가능한 동작을 보인다. 제안 페이지는 줄 끝에 새 제안 점을 표시하고 줄을 선택하면 열람을 기록한다. 노트 목록의 동작은 후속이다. 개수는 적지 않는다.
- 새로 온 것(새 제안, 확인할 메모리 변경)은 `text` 점이다. 그 줄을 보면 사라진다.
- 대화의 열람 시각은 내용을 연 뒤 기록한다. 한 번 선택하거나 페이지를 열어도 시각은 바뀌지 않는다. 답변 대기는 같은 대화의 다음 요청이 줄에서 실제 전송으로 넘어갈 때 해소한다. 두 실행기의 현재 이벤트에는 확인 요청 신호가 없어 답의 문장으로 대기를 추측하지 않는다.
- 꼭 봐야 하는 것(답이 필요한 대화와 루틴, 막힌 루틴)은 `warn` 점이다. 답하거나 풀려야 사라진다.
- 둘이 함께면 `warn` 점 하나만 보인다.
- 사이드바의 에이전트 줄, 페이지 안의 그 줄, 메모리의 기억 세그먼트에 같은 점을 쓴다. 지침에는 붙지 않는다.

### 막혔을 때

- 막힌 까닭과 다음에 누를 것 하나만 보인다.
- 로그인 만료는 macOS 알림과 설정 상세의 띠(11장)로 알린다. 막대 요청 실패는 대화 안에 실패 이유와 다시 시도를 남기고 대화가 보이지 않으면 시스템 알림으로 알린다. 그 밖에는 짧은 알림에 `다시 시도`를 둔다.
- 쓸 수 있는 양을 다 썼으면 다시 되는 시각을 알린다.

### 새 요소

토큰 이름은 제안 이름이다. `tokens.json`에는 구현할 때 넣는다. 어두운 화면 값은 구현 뒤 캡처로 정한다.

| 제안 이름 | 값(밝은 화면) | 쓰이는 곳 |

| `agent-bg-a`, `agent-bg-m`, `agent-bg-b` | #EEEBF7, #F5F0F2, #F9EFE8 (이 순서로 번짐) | 받지 않은 제안의 카드와 연결 줄, 일하는 중 알림과 줄 |

| `agent-shimmer` | #6A5B9E | 일하는 중 글자 흐름의 띠 |
| `diff-add` | #E4F3E6 | 미리보기에서 더하는 줄의 바탕 |

팝오버 그림자는 기존 메뉴의 값을 그대로 쓴다. 버튼은 기존 동작 버튼(흰 바탕, 옅은 테두리)이고 삭제는 글자만 `warn`이다.

### 단계

세 단계로 나누며 현재 범위는 이 장 첫 문단에 적었다(D-202).

| 단계 | 범위 | 끝나면 할 수 있는 것 |
| --- | --- | --- |
| 1 | 막대의 두 모드, 에이전트 창(대화, 지난 대화, 진행 펼쳐 보기, 가장자리의 색), 얼굴 상태, 노트의 표시와 화면 구석 단추, 제안 카드와 미리보기, 사이드바의 제안과 대화 페이지, 볼 것 있음 점, 더하는 제안(할 일, 리마인더와 일정, 새 노트)의 반영과 되돌리기, 메모리의 지침 문서, 막혔을 때의 안내 | 막대나 에이전트 창에서 일을 시키고, 제안을 미리 본 뒤 받거나 버리고, 지난 대화를 다시 연다. 지침을 적어 두면 그대로 따른다 |

| 3 | 메모리의 기억, 변경 기록과 되돌리기, 기억 정리, 일정에 맞춘 선제 알림 | 에이전트가 기억한 것을 보고 고치고 되돌린다. 일정 앞에 에이전트가 먼저 알린다 |
