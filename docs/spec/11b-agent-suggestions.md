## 11b. 제안

구현 상태: 아직 구현하지 않았다. 더하는 제안은 1단계, 고치는 제안과 종류별 바로 반영은 2단계다(11a의 단계 절).

근거는 에이전트 시안 최종판(2026-11-23)이다(D-193, D-194).

### 반영 방식

- 에이전트는 노트와 일정을 직접 바꾸지 않는다. 제안을 내고, 사용자가 받으면 앱이 반영한다(11장의 MCP는 계속 읽기만 한다, D-143).
- 받은 직후에는 짧은 알림에 `되돌리기`를 둔다.
- 설정의 에이전트, 반영 방식 카드에서 종류별로 `승인 후`와 `바로`를 고른다(세그먼트).

| 종류 | 고를 수 있는 것 |
| --- | --- |
| 할 일 추가 | 승인 후, 바로 |
| 리마인더와 일정 추가 | 승인 후, 바로 |
| 새 노트 만들기 | 승인 후, 바로 |
| 본문과 지침 고치기, 지우기, 옮기기 | 언제나 승인 후 |

기본값은 모든 종류에서 승인 후다. 새 노트 만들기도 직접 시킨 경우를 포함해 승인 후가 기본이다(D-203).

### 제안 카드

- 아직 받지 않은 제안은 에이전트 색 바탕과 점선 테두리의 카드다. 대상 노트 아래에 붙는다.
- 카드에는 제목, 짧은 미리보기, 오른쪽 아래에 `버리기`와 `받기`를 둔다. 미리보기를 누르면 노트 모양의 전체 미리보기가 열린다.
- 대상 없는 새 노트 제안은 대화의 결과 줄과 제안 페이지의 새 노트 미리보기에 둔다. 수락 전에는 노트를 만들지 않는다(D-211).
- 대화에는 결과로 가는 연결 줄(무엇을 했는지와 대상 노트 이름)을 둔다. 누르면 그 자리가 열린다.

### 미리보기

더하는 줄과 빼는 줄을 색으로 보인다. 더하는 줄은 +와 `diff-add` 바탕, 빼는 줄은 -와 `diff-del` 바탕이다. 기호는 따로 둔 칸(28pt)의 가운데에 둔다.

| 제안 | 미리보기 |
| --- | --- |
| 본문에 더하기 | 받은 뒤의 노트 전체를 보이고 더해지는 문단만 표시한다 |
| 투두 추가 | 체크 상자까지 실제 모양으로 |
| 본문 고치기 | 빼는 줄과 더하는 줄을 짝지어 보인다. 노트 모양을 본 뒤에만 받을 수 있다 |
| 일정 추가 | 노트 상단에 생길 칩과 다가오는 일정에 생길 줄 |
| 제목 바꾸기 | 제목을 한 줄로 보고 빼는 줄과 더하는 줄로. 머리 줄에는 새 제목 |
| 스페이스 옮기기 | 목록에서 빠지는 자리와 생기는 자리를 같은 표시로 |
| 새 노트 | 만들어질 노트를 노트 모양으로 |

### 버튼의 자리

- 카드와 미리보기 안의 동작은 오른쪽 아래에 둔다. 페이지 동작은 머리 오른쪽, 줄 동작은 그 줄에 올렸을 때 나타난다(D-212).
- 줄은 한 번에 하나만 고른다. 여러 줄을 함께 고르지 않는다.

### 제안 페이지

- 라이브러리 사이드바의 제안 줄을 누르면 열린다. 제안은 요청(대화나 루틴)별 묶음으로 보인다. 묶음 머리에는 요청 이름과 시각을 둔다.
- 묶음 머리에 올리면 시각 자리에 겹친 체크 둘(모두 받기)이 나타난다. 개별 줄은 받기 체크 하나와 버리기 x다(D-218).
- 창이 넓으면 고른 줄의 미리보기와 버튼을 오른쪽 칸에 둔다. 좁으면(660pt) 누른 줄 아래로 펼치고 다시 누르면 접는다.
- 새 제안이 있으면 사이드바의 제안 줄 끝에 점이 붙는다(11a).
