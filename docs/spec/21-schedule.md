## 21. 리마인더와 일정 (6단계)

2026-11-17 사용자 결정. 이슈 #4의 1~6번 답이며 D-067~D-073을 따른다.

### 종류, 저장, 캡처

- 종료가 있으면 일정, 없으면 리마인더다. 판정은 `ScheduleItem.kind` 한 곳이다. 날짜만 있는 리마인더도 허용한다.
- 노트마다 여러 예정(`schedules`)을 frontmatter의 한 줄 JSON 배열로 저장한다. 각 항목은 ID, 종류, 시작, 종료, 날짜만 여부, 선택한 임박 표시 시간(분), 완료, 제목, 원래 투두의 줄 번호, 정확한 글자, 로컬/외부 EventKit 식별자, 수정, 동기화 시각, 오류와 삭제 대기를 가진다. 종류는 종료 유무에서 결정되고 JSON에도 함께 적힌다.
- 기존 `reminder` 날짜는 안정된 `legacy-<noteID>` ID의 예정 하나로 읽는다. 새 파일에도 옛 앱용 `reminder` 날짜를 함께 적는다. 완료 항목만 있는 빈 노트도 옛 앱의 빈 노트 자동 삭제에 걸리지 않게 날짜를 남긴다. `schedules: []`는 옛 날짜를 다시 살리지 않는다.
- 5단계 실제 codec을 테스트에 고정해 새 파일 읽기와 옛 앱에서 제목을 바꿔 저장한 뒤 예정, 본문 보존을 검사한다. 옛 앱은 새 예정 목록을 편집하지 못하며, 새 목록이 있으면 그것이 정본이다.
- 빠른 캡처의 목적지는 D-026대로 스페이스의 오늘 노트다. 범위가 있으면 투두를 남기고 인식한 범위 글자만 뺀다. 시작, 종료를 모두 일정에 담는다. 지난 범위는 기존대로 글을 보존하고 등록하지 않는다. 단일 시각, 날짜 표현은 이번 단계에서 원문에 남긴다.
- 날짜만 있는 결과는 날짜 전용 예정으로 저장한다. `내일 저녁`처럼 때를 지정하면 기존 기본 시각을 쓴다. 종일 일정은 마지막 날 다음 자정을 배타적 종료로 저장한다. 설정 화면에는 마지막 날을 보여 준다.
- 본문, 제목에서도 공용 날짜 읽기를 사용한다. 제안을 Tab으로 받은 경우에만 표현을 제거하고 등록, 갱신한다(D-074~D-076).

### EventKit과 알림

- EventKit만 사용한다. 새 항목과 종류 전환은 설정에 저장된 종류별 캘린더 ID를 우선한다. 선택이 없으면 시스템 기본 캘린더(`defaultCalendarForNewEvents`)와 목록(`defaultCalendarForNewReminders()`)을 쓴다. 같은 종류의 기존 항목을 고칠 때는 연결된 대상을 유지한다. Mac 인터넷 계정의 Google 캘린더도 같은 경로다. Google API는 쓰지 않는다. 새 후보의 E2 이름과 색도 같은 대상에서 읽는다(D-100).
- 앱 설정의 예정 구획은 종류별 접근 상태를 확인한다. 기존 전체 권한이 있는 종류만 쓰기 가능한 목록을 읽고 시스템 기본값과 함께 보여 준다. 저장한 ID가 사라졌거나 읽기 전용이면 해당 선택을 지우고 시스템 기본값을 표시한다. 권한이 없다는 이유로 ID를 지우지 않는다.
- 앱 설정에서 권한은 연결 버튼을 누르면 미결정인 캘린더와 미리 알림을 차례로 요청한다. 허용된 종류는 같은 구획의 팝업에서 선택한다. 거부, 제한, 쓰기 전용은 해당 개인정보 보호 설정으로 연결한다. 창 열기, 탭 이동, 복귀는 요청하지 않는다(D-099).
- 예정 편집에서는 새 항목을 저장하거나 새 종류로 전환할 때, 빠른 캡처로 새 예정이 저장되거나 본문, 제목의 날짜 제안을 명시적으로 받을 때 해당 항목에만 한다. 본문 편집, 자동 저장, 앱 시작, 외부 변경에는 요청하지 않는다. 노트 단위가 아니라 항목 ID로 명시적인 저장 의도를 전달한다(D-071).
- 권한 없음, 거부, 제한, 쓰기 전용 상태는 앱 안에 보존하며 `syncError`나 불필요한 `schedules:` 줄을 쓰지 않는다. 읽기, 등록, 앱 알림 권한 요청도 하지 않는다. 전체 접근 확인 후 실제 연동에서 기본 대상 없음/읽기 전용 등으로 실패한 경우에만 오류를 남긴다. 모달 경고는 띄우지 않는다.
- 기존 `legacy-` 항목은 권한이 생긴 뒤에도 자동 등록하지 않는다. 사용자가 설정에서 그 항목을 열어 저장한 경우에만, 다가오는 미완료 항목을 등록한다. 그 저장 자체로 권한을 요청하지 않으며 지난 항목, 완료 항목은 등록하지 않는다. 본문만 편집한 옛 파일은 원래 머리글 표기를 보존한다.
- 연결된 리마인더는 Apple 미리 알림이 알린다. 시각이 있으면 절대 시각 알람, 날짜만이면 마감 날짜만 쓴다. Float의 같은 알림은 취소한다.
- 연결이 없는 시각 지정 예정의 연동 실패에서만 `UserNotifications`로 앱 알림을 예약한다. 이때 처음 필요한 알림 권한을 요청한다. 날짜만 있는 항목에는 임의 알림 시각을 만들지 않는다. 연결된 항목의 일시적 오류는 중복 알림을 만들지 않는다. 알림을 누르면 원래 노트를 연다.
- 앱을 다시 켜면 기존 예정을 권한 요청 없이 재개한다. 권한이 없으면 노트를 보존한다. 실제 EventKit 객체는 필요한 권한 확인/명시 요청까지 지연 생성한다.
- `--calendar fake` 또는 디버그의 `--debug-passive`는 EventKit, UserNotifications 모두 가짜 구현을 사용한다. 실제 구현 생성, 권한, 계정 조회가 없다.

시계 창에서 예정을 삭제하거나 동기화로 외부 삭제가 확인되면 본문 줄의 연결과 그 줄의 제안 닫힘 상태도 풀린다. 같은 줄에서 다시 Tab으로 등록할 수 있다.

### 사이드바의 다가오는 일정 (D-123)

로컬 기준 지금부터 7일 뒤 같은 시각 전까지의 미완료 항목을 시작순으로 합친다. 진행 중인 일정과 오늘의 날짜 전용 리마인더를 포함한다. 같은 연결의 같은 회차는 노트 항목을 우선한다. 캘린더 단독 조회는 기존 전체 접근 권한에서만 수행한다. 첫 다섯 줄과 모두 보기, 상세 열기 동작은 9장을 따른다.

### 표시와 설정 화면

- 노트 상단에는 미완료, 미삭제 예정이 하나라도 있으면 시계 버튼을 항상 표시한다. 도움말과 접근성 이름은 가장 이른 다가올 예정의 시간과 추가 건수를 제공한다. 지난 예정만 남으면 “이 노트의 일정”과 건수를 제공한다. 날짜만 있는 오늘 항목은 오늘 내내 예정이다.
- 공통 `ReminderPresentation`(D-066)을 쓴다. 일정 범위는 `내일 오후 3:00~4:00`, 날짜만이면 `내일`이다. 다른 날짜의 끝은 날짜도 표시한다. 공통 표시의 시간/남은 시간/아이콘 설정과 관계없이 노트 상단은 시계를 쓰고 도움말에 시간을 제공한다.
- 시각 지정 예정은 기본 30분 전부터 임박이다(D-298). 설정에서 10, 15, 30, 60분 중 고른다. 예정에 별도 값이 있으면 그 값을 적용하고, 없으면 현재 설정을 따른다. 판정과 다음 표시 갱신에 쓰는 앱 전용 값이며 캘린더, 미리 알림의 알람이나 동기화 값에는 포함하지 않는다(D-299). 노트 상단의 그림은 항상 시계이며 임박하면 `warn`, 평소와 지난 예정만 남았을 때는 `text-3`다. 접근성 이름에도 임박을 넣는다. 공통 표시에서는 임박에 `warn`과 굵은 글자를 쓰고 리마인더는 흔들리는 종, 일정은 캘린더다. 공통 표시의 지난 예정 색은 `warn`이다.
- 여러 항목 중 하나라도 연동에 실패하면 시계 도움말과 접근성 이름으로 알린다. 시계를 표시할 활성 예정이 없으면 별도의 흑백 느낌표로 알린다. 긴 제목은 시계와 다른 버튼의 자리를 확보하도록 줄인다.
- 본문 줄에 연결된 미완료, 미삭제 예정은 줄 오른쪽 첫 화면 줄 높이에 6pt 점 하나로 표시한다(D-303). 종류에 관계없이 평소와 지난 예정은 `text-3`, 임박은 `warn`이다. 같은 줄에 여러 개면 시작이 가장 이른 예정의 상태를 쓴다. 모든 줄에서 20pt를 비워 줄바꿈을 고정한다. 점의 누름 칸은 20pt, 호버 바탕은 `hover`, 모서리는 `r-control`, 커서는 화살표다. 접근성 이름은 공통 예정 이름을 쓴다. 하나면 점 아래에서 바로 편집하고 뒤로 가면 노트의 목록이다. 둘 이상이면 목록을 연다.
- 상단 시계는 현재 노트의 일정 목록을 연다. 머리는 일정 한 단어이며 미완료, 미삭제 항목을 시간순으로 표시한다. 리마인더 동그라미는 20pt 완료 버튼이다. 올리면 hover 바탕과 text 선을 쓰고 완료하면 채운 동그라미, text-3 제목과 취소선으로 표시한다. 이번에 완료한 줄은 목록을 닫을 때까지 남아 다시 눌러 완료를 풀 수 있다. 나머지 영역은 같은 창에서 편집 화면을 연다. 일정 막대에는 완료 동작이 없다.
- 뒤로, 종류 세그먼트와 삭제를 위에 둔다. 캘린더 색 점과 제목 17pt/600, 날짜와 시작~끝, 종일 스위치, 캘린더 팝업, 임박 표시 값 메뉴, 실제 연결이 있는 본문 줄 순서다. Tab 순서는 제목, 날짜, 시작, 끝, 종일, 캘린더, 임박 표시다. 종일이면 임박 표시 줄과 해당 Tab 자리를 숨긴다. 임박 표시 메뉴 첫 항목은 현재 설정을 담은 “기본(N분 전)”이며 구분선 뒤에 네 선택지를 둔다. 기본을 고르면 항목의 별도 값을 지운다. 바뀐 필드는 같은 항목 ID로 저장한다.
- 날짜 고르기는 너비 264pt다. DateTime 입력과 오늘, 내일, 다음 주, 일요일 시작의 연속 4주를 표시한다. 다음 주 아이콘은 13pt 칸에 둥근 달력 외곽과 가로 구분선을 시안의 선 굵기 1.4로 그린다. 트랙패드로 주를 넘기며 날짜 머리를 누르면 월 4열과 연도 이동으로 전환한다. 선택한 날은 지름 26pt, 선택한 달은 높이 24pt다. 오늘과 이번 달의 글자는 warn이다. 날짜 해석은 07a장을 따른다.
- 캘린더 팝업은 쓰기 가능한 대상만 나열한다. 사용자가 고른 대상 ID는 동기화 성공까지 해당 항목에 보관한다.
- 날짜 표시 설정은 `relative`(기본, 상대 날짜)와 `absolute`다. 절대 표시는 `11월 18일 오후 3:00~4:00`, 다른 연도는 연도도 붙인다. `app-settings.json`의 `scheduleDateFormat`에 저장하고 공통 `ReminderPresentation`에서 처리한다. 시간/남은 시간/아이콘 모드와는 별도 값이다. 앱 설정의 예정 구획에서 고른다. 디버그 `schedule-format relative|absolute`로 저장과 즉시 반영을 확인한다(D-087).
- `reminder-editor-w` 332, `schedule-row-h` 42, 기존 예정 스크롤 최대 높이 `schedule-list-max-h` 240. 두 줄 구성에서 시간은 본문 글꼴의 같은 폭 숫자 11.5pt다(D-305). 새 항목 생성과 종류 전환의 권한 요청, 받기와 되돌리기, 양방향 연동은 기존 D-071을 유지한다.

### 양방향 반영과 충돌

- `EKEventStoreChanged`를 받으면 연결된 항목을 다시 읽고 열린 라이브러리의 일정 범위도 갱신한다. 로컬 ID를 먼저 확인하고 외부 ID로 다시 찾는다. 외부 ID가 중복이면 추측하지 않고 오류로 남긴다.
- 바깥의 시간, 종료, 날짜만 여부, 완료, 항목 제목을 갱신한다. 노트 제목과 본문은 보존한다. 완료 변경만 원래 투두 체크에 반영한다. 같은 글자의 투두가 여러 개이거나 원문이 바뀌어 찾을 수 없으면 임의의 줄을 체크하지 않는다. 코드 블록의 줄도 제외한다.
- 앱 투두 체크/해제는 연결된 미리 알림 완료/해제로 보낸다. 설정에서 완료를 바꿔도 연결 투두를 체크한다. 항목 삭제는 외부에서도 삭제한다. 실패하면 연결과 삭제 대기를 보존해 다음 변경 알림/재실행 때 다시 시도한다.
- 노트 파일의 외부 삭제 후 '새 노트로 저장'은 항목 ID만 새로 만들고 외부 연결, 동기화 기준, 오류, 삭제 대기를 보존한다. 연결의 새 주인에서 삭제도 재시도한다. legacy 표식도 유지해 복구가 자동 이관을 유발하지 않는다(D-072).
- 외부 삭제는 예정과 연결만 제거하고 노트, 글은 남긴다. 권한 거부나 조회 실패는 삭제로 간주하지 않는다.
- 노트를 휴지통으로 옮기면 Float 알림을 취소하고, 미완료, 미삭제 예정의 외부 항목을 지운다(D-304). 실패한 연결은 휴지통 파일에 보관해 외부 변경이나 재실행 때 다시 시도한다. 실제로 지운 항목만 휴지통 알림에 센다. 종류가 섞이면 “예정 N개도 지웠습니다”라고 표시한다.
- 휴지통 알림의 되돌리기, ⌘Z, 라이브러리의 되살리기는 같은 저장 경로를 쓴다. 되살린 미래 예정은 기존 권한으로 외부 항목을 다시 만들고 새 식별자를 저장한다. 삭제 대기 중이어서 외부에 남아 있으면 기존 연결을 이어 쓴다. 지난 예정은 새로 만들지 않는다. 로컬 시각 알림은 기존 권한으로 다시 예약하고 외부 연결을 복구하면 중복 알림을 취소한다. 보관함이나 스페이스 이동은 외부 항목을 유지한다.
- 마지막 동기화 값과 비교해 같은 초의 외부 수정도 감지한다. 양쪽 값이 달라졌다면 마지막 수정 시각이 더 늦은 쪽을 선택하고 충돌을 기록한다. 동률은 로컬을 따른다. EventKit은 삭제 시각을 제공하지 않으므로 외부 항목이 사라진 경우에는 삭제를 우선해 임의 재생성을 막는다.
- 동기화는 직렬화한다. 권한 대기 후 최신 노트를 다시 확인하고, 항목 단위로 저장한다. 파일 충돌은 D-016대로 유지하며 원문 전체를 외부 값으로 덮어쓰지 않는다.

### Apple 1차 자료와 확인 한계

- [Event Store 접근과 전체 접근 요청](https://developer.apple.com/documentation/eventkit/accessing-the-event-store)
- [TN3153: macOS 14 이후 권한 API와 사용 설명 키](https://developer.apple.com/documentation/technotes/tn3153-adopting-api-changes-for-eventkit-in-ios-macos-and-watchos)
- [변경 알림과 재조회](https://developer.apple.com/documentation/eventkit/updating-with-notifications)
- [EKEventStore.init](https://developer.apple.com/documentation/eventkit/ekeventstore/init())은 생성만 설명한다. 생성만으로 창이 뜨지 않는다는 명시 보장은 찾지 못했다. 따라서 실제 객체를 지연 생성하고 검증은 가짜만 사용한다.
- Info.plist: `NSCalendarsFullAccessUsageDescription`, `NSRemindersFullAccessUsageDescription`. D-063대로 Hardened Runtime은 켜지 않는다.

### 본문, 제목 연결과 되돌리기 (D-075, D-076)

- `inlineSource`는 제목(줄 번호 없음) 또는 본문 줄 번호, 정확한 원문을 저장한다. 투두이면 기존 `TodoAnchor`도 함께 저장해 완료를 양방향으로 반영한다. 일반 줄은 완료 체크를 만들지 않는다.
- 같은 연결에서 새 날짜를 받으면 ID를 유지하고 시작, 종료, 날짜만 여부를 갱신한다. 제목은 제목에서 받은 항목 하나를 갱신하고, 수동 설정의 다른 항목과 다른 줄의 예정은 보존한다. 빠른 캡처의 투두도 글자가 유일하면 기존 연결을 재사용한다.
- 본문의 한 줄 편집, 위아래 줄 삽입, 유일한 원문 줄의 이동은 연결이 따라간다. 여러 줄 합치기, 분할이나 중복 원문 때문에 식별이 모호하면 추측해서 다른 투두를 체크하지 않는다. 중복 연결이 있는 받기도 원문을 보존한 채 거부한다.
- 노트 본문 편집기에서 한 편집으로 연결된 줄을 지우면 체크 줄, 글머리표, 일반 줄에 연결된 예정도 함께 지운다(D-300). 외부 삭제 실패는 기존 삭제 대기로 보관한다. 중복 원문으로 모호하면 연결만 푼다. 제목 연결, 바깥 파일 변경, 동기화, 에이전트 편집, undo 재생으로 새 삭제를 만들지 않는다.
- 노트 아래 가운데에 “리마인더도 지웠습니다”, “일정도 지웠습니다” 또는 “예정 N개도 지웠습니다”와 “되돌리기”를 표시한다. 알림과 ⌘Z는 같은 편집 단계에서 줄과 예정 모두를 복원한다. 이미 지운 외부 항목은 기존 권한으로 다시 만들고 새 식별자를 연결한다. 잘라내기와 붙여넣기가 별도 편집이면 붙여넣기만으로 예정이 돌아오지 않는다.
- ⌘Z는 생성한 항목을 삭제하거나 갱신 전 시간을 복원한다. 외부 항목이 이미 있으면 최신 연결 ID로 삭제/복원하며, 삭제 실패는 기존 삭제 대기로 보존해 재시도한다. 권한 응답 전에 되돌린 항목은 응답 뒤에도 등록하지 않는다. 다시 하기는 이미 허용된 권한만 사용한다.
- 본문은 `UndoHistory`의 단계에 효과 ID를 함께 적고, 제목은 AppKit의 한 undo 동작으로 묶는다. 제목 문자열 직접 대입으로 기존 undo를 초기화하지 않고 텍스트 저장소만 수정한다. 제목 받기 후 Escape의 편집 취소 기준은 받은 뒤 제목이다. 원문이 바깥 편집과 겹쳐 undo 단계를 유지할 수 없으면 기존 D-037대로 그 단계를 버린다.
- 새 연결은 기존 권한 정책을 따르며, 종류를 바꾸는 갱신은 새 종류에만 명시 요청한다. 제안 표시, 일반 입력, 자동 저장은 권한을 요청하지 않는다.
