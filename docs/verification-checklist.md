# 손으로 확인할 목록

자동 확인(테스트, 키 창을 만들지 않는 확인용 실행)으로는 보지 못한 것들이다. 실제 키보드와 마우스로 한 번씩 본다.
항목은 "하는 일: 기대하는 결과"다. 다르게 보이면 그 줄을 그대로 알려 주면 된다.

## 켜는 법

- 실제 노트로 켜기: `scripts/run.sh` (릴리스 빌드를 만들고 앞에서 실행한다). 노트는 `~/Library/Application Support/FloatingNotes/notes`, 창 상태는 같은 폴더의 `state`에 있다.
- 실제 노트를 건드리지 않고 켜기: `scripts/run.sh --notes-dir /tmp/fn-check` (그 폴더만 읽고 쓴다. 지우면 처음 상태로 돌아간다).
- 모양 고정: `--appearance light|dark`. 메뉴 막대 아이콘 끄기: `--menu-bar-icon off`.
- 끝내기: 앱 메뉴의 종료(⌘Q) 또는 메뉴 막대 메뉴의 종료.

## 한글 입력 (두벌식)

- [ ] 노트 본문에 "안녕하세요 반갑습니다"를 빠르게 친다: 글자가 빠지거나 겹치지 않고, 조합 중인 마지막 글자가 제자리에서 바뀐다.
- [ ] 노트 본문에서 한글을 치다가 조합 중에 ↵: 마지막 글자가 확정되고 줄이 한 번만 바뀐다(빈 줄이 두 번 생기지 않는다).
- [ ] `[]` 뒤에 Space, 이어서 한글을 친다: 체크박스가 생기고 한글이 그 뒤에 들어간다.
- [ ] 노트 제목 칸에 한글을 치고 ↵: 제목이 확정되고 커서가 본문으로 간다.
- [ ] 캡처 바에 "우유 사기"를 치고 조합 중에 ↵ 한 번: 마지막 글자까지 든 "우유 사기"가 오늘 노트에 들어가고 바가 닫힌다(↵를 두 번 누르지 않아도 된다).
- [ ] 캡처 바에 "내일 오전 10시 회의"를 친다: "내일 오전 10시"에 밑줄이 그어지고 오른쪽에 "내일 10:00 AM"이 보인다. 치는 동안 조합이 끊기지 않는다.
- [ ] 노트 찾기에 "회"까지만 친다(조합 중): 제목이나 본문에 "회의"가 든 노트가 바로 걸러진다.
- [ ] 노트 찾기에서 한글을 치다가 조합 중에 ↵ 한 번: 고른 줄의 노트가 열린다.
- [ ] 한글 입력 상태에서 ⌘P, ⌘N, ⌘W, ⇧⌘T를 누른다: 영문 입력일 때와 똑같이 동작한다.

## 본문 편집기의 서식과 되돌리기

테스트는 실제 입력 경로(`insertText`, `doCommand(by:)`, `setMarkedText`)로 넣고 원문을 견준다. 실제 키보드와 입력기로는 보지 못했다.

- [ ] 노트에 `if a == 1 && b == 2`, `2 ** 3 ** 4`, `x==1&y==2`를 친다: 친 글자가 그대로 보인다(기호가 사라지거나 형광펜이 입혀지지 않는다).
- [ ] `**굵게**`를 치고 바로 ⌘Z: 굵은 글이 풀리고 `**굵게**`가 글자 그대로 보인다. 이어서 글을 쳐도 다시 굵어지지 않는다. ⌘Z를 한 번 더 누르면 마지막 `*`가 지워진다.
- [ ] ⌘B를 누르고 한글로 "가 나 다"를 친다(두벌식, 띄어쓰기 포함): 세 낱말이 모두 굵고, 치는 동안 `**`가 잠깐이라도 보이지 않는다. 낱말 사이의 공백에서 조합이 끊기지 않는다.
- [ ] 굵은 글자를 모두 고르고 한글 자음 하나를 친 뒤 ⌫로 지운다: 빈 줄이 되고 `****`가 남지 않는다.
- [ ] 글을 여러 낱말 치고 ⌘Z를 누른다: 낱말 단위로 되돌아간다(글자 하나씩도, 전부 한꺼번에도 아니다). ⇧⌘Z로 다시 돌아온다. 편집 메뉴의 "실행 취소"가 되돌릴 것이 없을 때 흐리다.
- [ ] 빈 줄에 백틱 셋, 이어서 `swift`, ↵: 코드 블록이 생기고 `swift`는 보이지 않는다(파일에는 여는 줄에 남는다). 이어서 친 글이 첫 코드 줄에 들어간다.
- [ ] 코드 블록의 빈 줄에서 백틱 셋: 블록 아래의 문단으로 나간다. 아래의 글이 코드로 바뀌지 않는다.
- [ ] 다른 편집기에서 복사한 ` ``` ` 블록을 글이 있는 줄 끝에 붙인다: 블록이 다음 줄에 놓이고 그 아래의 글은 그대로다.
- [ ] 빈 줄에 백틱 셋, 이어서 `ls`, ↵: `ls`가 코드 줄로 남고 그 아래에 빈 코드 줄이 생긴다(`ls`가 사라지지 않는다).
- [ ] `a==b 인지 ==확인== 하자`를 친다: `a==b 인지`가 그대로 보이고 `확인`만 형광펜이다. `2**3**4`, `a==b==c`를 쳐도 글자가 사라지지 않는다.
- [ ] `foo **bar** baz`에서 `bar` 앞의 공백을 지운다: 굵은 글이 그대로다. 이어서 뒤의 공백을 지운다: 알림음이 나고 글이 바뀌지 않는다(굵은 글이 풀리지 않는다).
- [ ] ⌘B를 누르고 한글 자음 하나를 친 채(조합 중) 다른 창을 누른다: 그 글자가 굵게 남는다(`**`가 사라져 보통 글자가 되지 않는다). 조합 중에 ⌘Z, ⇧⌘Z를 눌러도 같다. 테스트는 입력기 없이 `setMarkedText`와 `makeFirstResponder(nil)`로만 봤다.
- [ ] 노트 끝의 글자를 ⌫로 지우고 ⌃⌥N으로 한 줄을 캡처한 뒤 노트에서 ⌘Z: 지운 글자가 제자리(캡처한 줄 앞)에 돌아오고, ⌘Z를 더 눌러 그 전의 편집도 되돌릴 수 있다.
- [ ] 코드 블록 안에서 `x` 뒤에 백틱 셋을 친 줄의 `x`를 지운다: 알림음이 나고 지워지지 않는다. 알림음이 시스템 경고음으로 들리는지 본다(테스트는 소리를 내지 않고 횟수만 센다).

## 본문 편집기의 입력 커서, 하위 계층, 인용문

테스트는 화면에 올리지 않은 창에서 커서의 틀과 원문을 견주고, 확인용 실행 파일(`EditorDemo --activate --quit-after 4`)로 키 창에서 몇 장 찍어 봤다. 실제 입력기와 오래 쓰는 동안의 모습은 보지 못했다.

- [ ] 본문, 제목 1, 인라인 코드 안, 코드 블록, 빈 줄에 커서를 둔다: 커서가 얇고(`caret-w`), 높이가 그 자리 글자 높이다(제목은 크고 코드는 작다). 줄 높이 전체를 덮지 않는다.
- [ ] 글을 치고, 화살표로 옮기고, 다른 곳을 누르고, 다른 창을 눌러 키 창을 바꾸고, 스크롤하고, 다크 모드를 바꾸고, ⌘Z를 누른다: 어느 때에도 커서 자국이 글자 위에 남지 않고 커서가 둘로 보이지 않는다.
- [ ] 한글을 조합하는 중: 커서가 조합 중인 글자 바로 뒤에 있다.
- [ ] 긴 줄이 넘어가는 자리에서 End, →, ←: 커서가 윗줄 끝과 아랫줄 앞 사이를 오가며 엉뚱한 줄에 서지 않는다.
- [ ] 노트 제목 칸의 커서: 노트 창에 `ThinCaretFieldEditor`를 붙이기 전에는 시스템의 커서다(붙이는 법은 architecture.md의 Theme 절).
- [ ] 본문 줄이나 빈 줄에서 Tab을 여러 번: 들어가지 않는다. 글머리표 아래 줄에서 Tab: 한 단계만 들어가고 안내선이 부모 글머리 아래에 선다.
- [ ] 하위 항목이 있는 글머리표의 기호를 ⌫로 지운다: 하위 항목이 한 단계 나온다. ⌘Z 한 번에 돌아온다.
- [ ] 하위 항목이 있는 글머리표 끝에서 Return 두 번 뒤 영문과 한글(실제 입력기)로 친다: 아래 하위 항목이 움직이지 않고, 두 입력이 같은 글을 남긴다.
- [ ] 빈 줄에 `"` Space, `|` Space: 인용문이 되고 왼쪽에 막대가 선다. Return으로 이어 쓰면 막대가 이어지고, 빈 줄에서 Return을 한 번 더 누르면 인용문에서 나온다.
- [ ] `>` Space: 토글이 되고 파일에는 `+ `로 적힌다. 예전에 `> `로 적어 둔 토글이 든 노트는 인용문으로 보인다(사용자가 받아들인 변화).
- [ ] 코드 블록에 마우스를 올리고 오른쪽 위 복사 버튼 위로 옮긴다: 화살표 커서다(I자가 아님).

## 전역 단축키와 Raycast

- [ ] 다른 앱(예: 브라우저)을 쓰는 중에 ⌃⌥N: 캡처 바가 화면 가운데 아래쪽에 뜨고 바로 글을 칠 수 있다. 메뉴 막대의 앱 이름은 쓰던 앱 그대로다.
- [ ] 캡처 바가 떠 있을 때 ⌃⌥N을 다시 누른다: 바가 닫히고 쓰던 앱에서 이어서 칠 수 있다.
- [ ] 다른 앱을 쓰는 중에 ⌃⌥H: 떠 있는 노트가 모두 사라진다. 다시 누르면 제자리에, 겹친 앞뒤 그대로 돌아오고 쓰던 앱의 입력을 가져가지 않는다.
- [ ] 켠 터미널의 기록에 "전역 단축키 … 등록하지 못했습니다"가 없다. 있으면 그 키를 다른 앱이 쓰고 있는 것이다.
- [ ] Raycast 설정의 단축키 목록에 ⌃⌥N, ⌃⌥H가 없다. 있다면 누가 받는지 본다: 이 앱은 독점으로 등록하므로 이 앱이 켜져 있는 동안 Raycast 쪽이 듣지 못할 수 있다.
- [ ] ⌃⌥L, ⌃⌥A를 누른다: 아무 일도 없다(화면이 아직 없어 등록하지 않았다). 다른 앱이 그 키를 쓰고 있으면 그 앱이 받는다.

## 빠른 캡처

- [ ] 노트에 글을 쓰던 중에 ⌃⌥N, 글을 적고 ↵: 줄이 오늘 노트 맨 아래에 투두로 붙고, 그 노트가 떠 있으면 창에 바로 보인다. 키 입력은 쓰던 노트로 돌아와 커서가 있던 자리에서 이어서 쳐진다.
- [ ] 이어서 그 노트에 글을 더 치고 잠깐 기다린 뒤 파일을 열어 본다: 캡처한 줄과 친 글이 둘 다 있다.
- [ ] 캡처 바에서 esc: 닫히고 쓰던 노트(또는 쓰던 앱)로 키 입력이 돌아간다.
- [ ] 캡처 바가 떠 있을 때 바 바깥(다른 앱의 창, 노트 창, 바탕 화면)을 누른다: 바가 닫히고 누른 곳이 입력을 받는다.
- [ ] 오늘 노트 본문 맨 끝의 빈 줄에 커서를 두고 ⌃⌥N, 글을 적고 ↵, 이어서 그 노트에 글을 친다: 캡처한 줄이 본문 맨 아래에 붙고, 이어서 친 글은 그 줄 앞에 끼지 않고 제 줄에 들어간다.
- [ ] 오늘 노트 본문 끝에 빈 줄을 하나 더 두고(맨 끝에서 ↵) 글을 조금 친 뒤 같은 일을 한다: 캡처한 줄이 마지막 글 줄 바로 아래에 붙고 이어서 친 글이 제 줄에 들어간다. ⌘Z를 누르면 캡처한 줄이 아니라 캡처 전에 친 글이 차례로 되돌아간다.
- [ ] 다른 앱을 쓰는 중에 ⌃⌥N, 글을 적고 ↵를 빠르게 두 번 누른다: 오늘 노트에 투두가 정확히 하나만 들어간다. 경고음이 나지 않는다.
- [ ] 글을 적고 ⌘↵: 그 글이 제목인 새 노트가 뜨고 커서가 그 노트 본문에 있다.
- [ ] 노트 폴더를 읽기 전용으로 바꾸고(`chmod 555 <notes 폴더>`) 캡처 바에 글을 적고 ⌘↵: 알림 창이 뜨고, 닫으면 캡처 바가 적은 글 그대로 떠 있어 이어서 칠 수 있다. 권한을 되돌리고(`chmod 755`) 다시 ⌘↵를 누르면 그 글이 제목인 노트가 뜬다.
- [ ] 캡처 바가 떠 있는 채로 화면을 잠그거나 디스플레이를 재웠다가 깨운다: 보이지 않는 캡처 바가 남아 키 입력을 먹지 않는다. 쓰던 앱(또는 노트)에 바로 글이 쳐지고, ⌃⌥N을 누르면 캡처 바가 새로 뜬다.
- [ ] ⇥를 누른다: 오른쪽의 스페이스가 차례로 바뀐다(스페이스가 없으면 아무것도 보이지 않는다).
- [ ] 캡처 바가 나타나고 사라지는 모습: 조금 아래에서 떠오르며 나타나고, 내려가며 흐려진다. 바 안의 글자와 아이콘은 서로의 자리가 그대로다.

## 노트 찾기

- [ ] 노트의 더 보기 메뉴에서 노트 찾기를 고른다: 그 노트 상단 줄 바로 아래에 목록이 붙어 뜨고 검색 칸에 커서가 있다. 그 노트는 목록에 없다.
- [ ] 노트에 글을 쓰던 중에 ⌘P: 같은 자리에 뜬다. esc를 누르면 닫히고 쓰던 노트에서 이어서 쳐진다.
- [ ] 메뉴 막대 메뉴(또는 Dock 메뉴, 앱 메뉴)의 "노트 찾기": 화면 가운데 위쪽에 뜨고 모든 노트가 보인다.
- [ ] ↑↓로 줄을 옮기고 ↵: 떠 있는 노트면 그 창이 앞으로 오고 커서가 그 노트로 간다. 닫혀 있던 노트면 새 창으로 뜬다.
- [ ] 없는 말을 치고 ↵: "새 노트 만들기" 줄이 골라져 있고, 그 말이 제목인 새 노트가 뜬다.
- [ ] 노트 찾기가 떠 있을 때 바깥을 누른다: 닫히고 누른 곳이 입력을 받는다.
- [ ] 검색어를 치고 esc, 곧바로 ↵를 누른다: 아무 노트도 열리지 않고 새 노트도 만들어지지 않는다.
- [ ] 목록 맨 아래에 "라이브러리 열기"가 없다(라이브러리가 생기면 돌아온다, D-034). 메뉴 막대 메뉴와 Dock 메뉴, 앱 메뉴의 라이브러리, AI 패널, 설정, 단축키와 노트의 더 보기 메뉴의 리마인더 설정, 스페이스 옮기기, AI 패널 열기는 흐리게 보이고 눌리지 않는다.
- [ ] 노트 찾기가 떠 있는 동안 다른 노트를 닫거나 핀을 끈다(트랙패드로): 목록의 "떠 있는 노트"와 핀 표시가 따라 바뀐다.
- [ ] 노트 몇 개를 차례로 열었다 닫은 뒤 노트 찾기를 연다: "최근에 연 노트"가 방금 연 차례(가장 최근이 위)다.
- [ ] 노트 찾기가 떠 있을 때 ⌃⌥N: 노트 찾기가 닫히고 캡처 바가 뜬다. 그 반대(캡처 바에서 ⌘P)도 같다. 둘이 함께 떠 있지 않다.
- [ ] 캡처 바나 노트 찾기에서 ⌘W: 그 화면이 닫히고(esc와 같다) 쓰던 노트에서 이어서 쳐진다. 경고음이 나지 않고 노트 창은 닫히지 않는다. 다른 앱을 쓰다가 ⌃⌥N으로 연 캡처 바에서도 같다. 한글 입력 상태에서도 같다.

## 노트를 닫거나 휴지통으로 보낸 뒤의 키 입력

- [ ] 노트 둘을 띄우고 앞의 노트에 커서를 둔 채 ⌘W: 그 창만 내려가고 남은 노트에 커서가 간다. 바로 글을 치면 남은 노트에 들어간다.
- [ ] 노트 둘 가운데 커서가 있는 노트를 휴지통 아이콘으로 보낸다: 남은 노트가 키 입력을 받는다. 곧바로 ⌘Z를 누르면 보낸 노트가 제자리에 돌아온다.
- [ ] 다른 앱을 쓰다가 노트를 눌러 글을 쓰고 그 노트를 ⌘W로 닫는다(남은 노트 없음): 메뉴 막대는 "플로팅 노트" 그대로이고(노트를 누를 때 앱이 앞으로 왔다), 다른 앱을 누르면 그 앱이 입력을 받는다.
- [ ] 마지막 남은 노트를 휴지통으로 보낸 뒤 곧바로 ⌘Z: 메뉴 막대가 "플로팅 노트"이고, 노트가 같은 자리, 같은 크기, 같은 접힘으로 돌아와 커서가 본문에 있다.
- [ ] 노트를 휴지통 아이콘으로 보낸다: 그 화면 가운데 아래쪽에 "휴지통으로 보냈습니다"와 "되돌리기"가 잠깐 뜨고, 쓰던 곳의 입력을 가져가지 않는다. "되돌리기"를 한 번 누르면 노트가 제자리에 돌아오고 알림이 사라진다. 다시 보낸 뒤 ⌘Z로 되돌리면 알림도 사라진다. 4초쯤 뒤에는 스스로 흐려져 사라진다.
- [ ] 다른 앱을 쓰는 중에 ⌃⌥N, 글을 적고 ↵(오늘 노트가 화면에 없을 때): 화면 아래쪽에 "“오늘 노트 제목”에 넣었습니다"와 "열기"가 뜨고 메뉴 막대는 쓰던 앱 그대로다. "열기"를 누르면 그 노트가 뜨고 앱이 앞으로 온다. 오늘 노트가 이미 떠 있으면 알림이 뜨지 않는다.
- [ ] 휴지통으로 보낸 뒤 다른 노트에 글을 한 자 치고 ⌘Z: 노트가 돌아오지 않고 방금 친 글자가 지워진다.

## 노트 창 다루기

- [ ] 상단 줄(제목 옆 빈 곳)을 끌어 옮긴다: 창이 따라오고 놓은 자리가 다시 켜도 그대로다. 본문을 끌면 창이 움직이지 않고 글자가 선택된다.
- [ ] 창의 좌우 가장자리를 끌어 너비를 바꾼다: 260에서 560 사이에서만 바뀌고 글이 그 너비에 맞춰 다시 흐른다. 높이는 내용을 따라간다.
- [ ] 글을 여러 줄 더 친다: 창이 위쪽을 지킨 채 아래로 부드럽게 늘고, 화면 높이의 70%나 화면 아래 끝에서 멈춘 뒤 안에서 스크롤된다.
- [ ] 글을 다 지운다: 창이 줄어들되 본문 네 줄 높이에서 멈춘다.
- [ ] 마우스를 노트 위로 올린다: 더 보기, +와 오른쪽 아래의 휴지통, 닫기가 부드럽게 나타난다. 제목이나 다른 요소가 밀리지 않고 창 크기도 그대로다.
- [ ] 글을 쓰는 중에 마우스를 창 밖으로 뺀다: 버튼이 사라지고 글자와 커서만 보인다. 창의 바탕, 테두리, 그림자는 포커스가 있든 없든 같다.
- [ ] 버튼 위에 마우스를 올린다: 화살표 그대로이고(손가락 모양이 아님) 그 아이콘에만 옅은 상자가 생긴다. 본문 위에서만 I자 커서다.
- [ ] 다른 앱을 쓰는 중에 노트에 마우스만 올린다: 쓰던 앱의 입력이 노트로 넘어가지 않고 메뉴 막대도 그대로다. 노트를 눌러야 넘어간다.
- [ ] 다른 앱을 쓰는 중에 노트 본문을 누른다: 메뉴 막대가 "플로팅 노트, 파일, 편집, 보기, 창, 도움말"로 바뀌고 커서가 그 노트에 있다. 메뉴 어디에도 단축키 글자가 없다. 다른 앱을 누르면 노트는 그대로 보이고 핀이 켜진 노트는 그 앱 위에 남는다.
- [ ] 다른 앱을 쓰는 중에, 그리고 노트에 커서가 깜박이는 중에 핀, 더 보기, +, 휴지통, 닫기를 아이콘 한가운데와 가장자리, 창 모서리 쪽에서 한 번씩 누른다: 모두 한 번에 동작한다. 마우스가 막 노트에 들어와 아이콘이 나타나는 중에 눌러도 같다.
- [ ] 상단 줄의 아이콘 셋(더 보기, +, 핀)과 오른쪽 아래의 휴지통, 닫기: 높이가 고르고 가운데 선이 맞으며 서로 가까이 붙어 있다. 아이콘에 마우스를 올리면 그 아이콘에만 옅은 상자가 생긴다(휴지통과 닫기 모두). 핀 아이콘의 오른쪽 여백이 제목의 왼쪽 여백과 같아 보인다.
- [ ] 더 보기 메뉴를 흰 노트와 색 노트 위에서 연다(라이트와 다크): 바탕이 비치지 않고 글자가 또렷하며, 고를 수 없는 항목(리마인더 설정 등)은 눈에 띄게 흐리다. 메뉴 막대 메뉴도 같다.
- [ ] 메뉴 막대의 아이콘: 옆의 시스템 아이콘들과 좌우 여백이 같다.
- [ ] 아무것도 적지 않은 새 노트(⌘N)를 ×로 닫는다: 노트 찾기에 "제목 없음" 줄이 남지 않는다. 제목이나 글이 한 자라도 있으면 남는다. 빈 노트를 띄운 채 앱을 끝냈다 켜도 남지 않는다.
- [ ] 핀을 끈 노트: 다른 앱의 창을 누르면 그 뒤로 간다. 핀을 켠 노트는 전체 화면 앱 위에서도 보인다.

## 여러 화면

- [ ] 노트를 보조 화면으로 옮기고 앱을 다시 켠다: 같은 화면의 같은 자리에 뜬다.
- [ ] 보조 화면을 뽑고 다시 켠다: 그 화면에 있던 노트가 남은 화면 안으로 들어와 상단 줄을 잡을 수 있다.
- [ ] 마우스를 보조 화면에 두고 ⌃⌥N: 캡처 바가 마우스가 있는 화면의 가운데 아래쪽에 뜬다.
- [ ] 보조 화면의 노트에서 돋보기를 누른다: 노트 찾기가 그 노트 아래, 같은 화면 안에 뜬다. 화면 아래쪽의 노트에서 열면 목록이 눌리지 않고 위로 올라가 뜬다.
- [ ] 화면 오른쪽 끝에 붙인 노트에서 ⌘N: 새 노트가 화면 밖으로 나가지 않는다.

## 설치

- [ ] `scripts/install-app.sh`: 실행 중인 앱이 있으면 저장하고 끝난 뒤 `/Applications/플로팅 노트.app`(쓸 수 없으면 `~/Applications`)에 새로 들어가고 그 경로가 찍힌다. Finder와 Dock에 "플로팅 노트"로 보인다.

## 메뉴 막대 아이콘을 끈 상태

- [ ] `scripts/run.sh --menu-bar-icon off`로 켠다: 메뉴 막대에 아이콘이 없다.
- [ ] Dock 아이콘을 오른쪽 버튼으로 누른다: 새 노트, 빠른 캡처, 노트 찾기, 라이브러리, AI 패널, 노트 모두 숨기기, 설정, 단축키가 있고 새 노트, 빠른 캡처, 노트 찾기, 노트 모두 숨기기가 동작한다. 라이브러리, AI 패널, 설정, 단축키는 흐리게 보이고 눌리지 않는다.
- [ ] 화면 위의 앱 메뉴: 같은 항목이 있고 어디에도 단축키 글자가 보이지 않는다.
- [ ] 노트를 모두 닫은 뒤 Dock 아이콘을 누른다: 노트 하나가 뜨고 커서가 그 본문에 있다.
- [ ] ⌃⌥N, ⌃⌥H, ⌘N, ⌘P가 아이콘이 있을 때와 똑같이 동작한다.

## VoiceOver 기본 (⌘F5)

- [ ] VO로 노트 창으로 옮겨 간다(VO+F1, F2 또는 창 고르기): 노트 창이 키 창이 되고 제목이 읽힌다.
- [ ] 본문으로 들어간다: 글이 줄 단위로 읽히고 글을 칠 수 있다. 체크박스 줄은 체크 여부가 읽히는지 본다(읽히지 않으면 알려 준다).
- [ ] 상단 줄의 버튼(더 보기, +, 핀)과 휴지통, 닫기: 이름이 읽히고 VO+Space로 눌린다.
- [ ] 캡처 바를 연다: 입력 칸으로 포커스가 가고, 오른쪽의 스페이스와 리마인더가 "스페이스 …", "리마인더 …"로 읽힌다.
- [ ] 노트 찾기를 연다: 검색 칸으로 포커스가 가고 ↑↓로 옮길 때 줄의 제목이 읽히는지 본다(읽히지 않으면 알려 준다).

## 노트 창 둘레의 검은 잔상

예전에 한 번 보인 것이다. 투명한 창의 그림자와 입력 커서 쪽을 고쳤지만 실제 화면에서 다시 봐야 한다. 밝은 바탕 화면 위에서 볼 때 잘 드러난다.

- [ ] 글을 쳐서 창 높이가 늘어난 직후와, 글을 지워 줄어든 직후의 창 아래쪽 가장자리와 모서리: 옛 크기의 그림자나 검은 띠가 남지 않는다.
- [ ] 토글을 접고 편 직후(높이가 크게 바뀐다)와 창 너비를 끌어 바꾼 직후: 창 둘레에 어두운 테두리가 남지 않는다.
- [ ] 입력 커서가 지나간 자리(빠르게 치거나 화살표로 옮길 때): 커서 자국이 줄처럼 남지 않는다.
- [ ] 노트 찾기에 글자를 쳐서 목록 높이가 바뀔 때의 목록 아래쪽: 옛 높이의 그림자가 남지 않고, 옛 줄과 새 줄이 겹쳐 보이지 않는다.
- [ ] 캡처 바가 사라진 자리, 노트를 닫거나 숨긴 자리: 창 모양의 어두운 흔적이 남지 않는다.
- [ ] 라이트와 다크를 바꾼 직후(시스템 설정)의 노트 창 모서리: 둥근 모서리 밖에 네모난 어두운 귀퉁이가 보이지 않는다.
- [ ] 다크에서 색 없는 노트는 거의 검정으로 보인다. 이것은 토큰 값(`surface` #000000) 그대로이며 잔상이 아니다(D-025).

## 화면이 잠겨 있을 때의 자동 확인

- [ ] 화면을 잠근 채로(또는 디스플레이를 재운 채로) 원격 셸에서 `cd App && swift test`: 모두 통과한다. 창의 움직임이 나아가지 않아도 상태가 전환 시간 뒤에 바뀌는지 본다(D-032의 7번).
